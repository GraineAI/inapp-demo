Integration guide · In-app agents

Put a Graine agent inside your app and website

Chat with interactive components, voice, WhatsApp-style calls, scheduled check-in calls and memory, in your iOS, Android, React Native or Flutter app, and on your website. You integrate with a publishable key and our SDKs. No server of your own is needed.

SDK 0.7 · React Native 0.41 · Website embed v1 Updated 13 October 2026 Audience app and platform engineers

App engineers can start at Before you start. Architects and reviewers can start at How it works and Data, privacy and security.

1 · Overview

What you're building

One agent, configured in the Graine dashboard, reaches your users in every way below. Each SDK draws the same experience, so your users get the same agent on every platform.

Chat with components

Text conversations where the agent shows cards, choices, lists and appointment slots, and acts inside your app.

Voice in the app

Users talk to the agent from the assistant bar, with live captions and low latency.

WhatsApp-style calls

A real phone-style call: CallKit on iPhone, a full-screen call on Android. It works with the screen locked.

Scheduled calls

The agent books a callback in conversation, your app books one, or your team books one in the dashboard. Graine rings the phone on time.

Memory

The agent remembers each user across chats and calls. Users can opt out, and you can erase a user.

Screen context

The agent knows which screen the user is on and what they are filling in, and can point at things or open screens.

2 · Architecture

How it works

Your app talks to Graine through the SDK, authenticated by a publishable key. Graine runs the conversation, remembers the user, schedules calls and rings devices through Apple and Google push services, using the push credentials you upload once.

flowchart LR
  subgraph App["Your app"]
    UI["Your screens"] --> SDK["Graine SDK"]
  end
  SDK -- "publishable key, secure connection" --> G["Graine"]
  G -- "conversation, components, actions" --> SDK
  G -- "VoIP push" --> APNs["Apple Push"]
  G -- "data message" --> FCM["Firebase Cloud Messaging"]
  APNs --> Phone["User's phone rings"]
  FCM --> Phone
  Dash["Graine dashboard"] -- "agent, memory, calls, design" --> G

The four ideas that make it work

  1. The publishable key identifies your agent, not your user. It is safe to ship in your app. It only opens conversations with the agent it belongs to, from the apps and sites you allow.
  2. Your app says who the user is, and Graine decides what counts as identity. In the dashboard you choose which field identifies a user (for example patient_id). The SDK sends that field once per conversation. Graine turns it into a one-way user key and never stores the value itself.
  3. Memory belongs to a user, and a user belongs to their devices. Each user key is bound to the devices that first used it (two by default). A different device claiming the same user gets no memory and receives no calls for that user.
  4. Calls ring without your server. You upload your APNs key and Firebase service account once. The SDK registers each device, and Graine rings it at the scheduled time, checking the user's local time and your calling rules first.

A scheduled check-in, start to finish

sequenceDiagram
  participant U as User
  participant A as Your app + SDK
  participant G as Graine
  participant P as Apple / Google push
  U->>A: "Call me tomorrow at 6 pm"
  A->>G: conversation (agent books the call)
  G-->>A: "Booked for 6:00 pm tomorrow"
  Note over G: next day, 6:00 pm in the user's timezone
  G->>G: checks credits, agent on, calling hours
  G->>P: ring device (no personal data in the push)
  P->>A: incoming call
  A->>U: CallKit / full-screen call
  U->>A: answers
  A->>G: joins the call (with the call id)
  G-->>A: agent speaks, knows why it is calling
  A->>G: outcome: answered, declined or missed
3 · Prerequisites

Before you start

  • A Graine workspace and an agent (Agents → New agent).
  • The agent's publishable key (pk_live_…) from Agent → Embed & Widgets. Add app:// to Allowed domains there so your mobile apps can connect, and your website's domain (for example care.example.com) for the website embed.
  • For incoming calls on iPhone: an APNs auth key (.p8) with its Key ID, your Team ID and your app's bundle ID. Create the key in Apple Developer → Keys with Apple Push Notifications enabled.
  • For incoming calls on Android: a Firebase service-account JSON for your app's Firebase project, and your app's package name. Your app already includes Firebase Cloud Messaging.
  • Platform minimums: iOS 15, Android 7.0 (API 24) with compile SDK 36, React Native 0.71, Flutter 3.19 (Dart 3.3).

8 · Identity and memory

Tell the SDK who the user is New

Call identify after your own sign-in, with the field you chose under Who is the user? plus anything the agent should know, such as a first name. Call it with null on sign-out.

const identify = useGraineIdentify();
const graine = useGraineClient();

useEffect(() => {
  if (patient) identify({ patient_id: patient.mrn, name: patient.firstName }, { memory: patient.memoryConsent });
  else identify(null); // sign-out: releases this device and stops calls for that user
}, [patient, identify]);

// later, from a settings screen
graine.setMemory(false);      // stop remembering this user
const remembered = await graine.memories();   // [{ id, text, createdAt, updatedAt }]
const erased = await graine.forgetMemory();   // erase what the agent remembers; returns how many
graine.identify(["patient_id": patient.mrn, "name": patient.firstName], memory: patient.memoryConsent)
graine.identify(nil)                 // sign-out

graine.setMemory(false)
let remembered = try await graine.memories()   // [GraineMemory]
let erased = try await graine.forgetMemory()   // how many were erased
graine.identify(mapOf("patient_id" to patient.mrn, "name" to patient.firstName), memory = patient.memoryConsent)
graine.identify(null)                // sign-out

graine.setMemory(false)
graine.memories { items, error -> /* [GraineMemory] newest first */ }
graine.forgetMemory { deleted, error -> /* how many were erased */ }
GraineInApp.instance.identify({'patient_id': patient.mrn, 'name': patient.firstName}, memory: patient.memoryConsent);
GraineInApp.instance.identify(null); // sign-out

GraineInApp.instance.setMemory(false);
final remembered = await GraineInApp.instance.memories();
final erased = await GraineInApp.instance.forgetMemory(); // how many were erased
// after your own sign-in; safe to call before load() finishes
GraineAgent.identify({ patient_id: patient.mrn, name: patient.firstName }, { memory: patient.memoryConsent });
GraineAgent.identify(null);                  // sign-out

GraineAgent.setMemory(false);
const remembered = await GraineAgent.memories();
const erased = await GraineAgent.forgetMemory();

What happens to the identifier

The SDK sends the identifier field only when a conversation starts. Graine immediately turns it into a one-way key scoped to your workspace, then discards the value. The key is the same every time for the same user, so memory and scheduled calls follow them across chat, voice and calls.

patient_id "MRN-000981" → u1_26emnecbtm4pktqzkxl3vmw2wu (example; your workspace's keys differ)

Other traits (name, plan) become context for the agent. Phone numbers, email addresses and government or card numbers in traits are masked on the device before anything is sent.

Rules worth knowing

  • Identity is read when a conversation starts. A change applies to the next conversation.
  • No identity, or a placeholder value such as "guest", "0" or "unknown", means the conversation has no memory. Strangers never share memories.
  • Phone calls are identified by the caller's number. If you choose Phone number as the in-app identifier, a user's phone and app conversations share one memory. Numbers match on their last 10 digits.
  • A device beyond the user's device limit gets no memory and no calls for that user. A device is released when the user signs out on it, after 30 days of inactivity, or when your team resets it in the dashboard.

10 · Voice

Voice in the app

The assistant bar starts a voice conversation with one tap, with live captions and an end button. It uses a low-latency real-time media connection and falls back automatically on networks that block it. Voice ends when the app goes to the background. For a conversation that continues with the screen locked, use a call.

11 · Calls

WhatsApp-style calls

A call is the phone's own kind of call. It rings over the lock screen, works with Bluetooth and continues in the background. It is the same agent, so it sees the user's screen and can run your actions.

What your users see

Every colour, the avatar, which controls appear, and each line of text (including "Scheduled call" and "Missed call") come from the Call screen tab in the Garage. See Design.

On the website

WhatsApp-style calls ring your apps. Website visitors talk by voice in the browser while the page is open. A call booked from the website (by the agent or with GraineAgent.scheduleCall) rings that user's app on their phone. If they have never signed in to your app, it ends as no_device.

Set up calls at launch

    displayName = "Care Coach",

Graine rings the user New

Once your in-app calling credentials are verified, each device registers itself and Graine rings it for every scheduled call. On iOS, nothing else is needed. On Android, pass Firebase messages and token refreshes to the SDK. That is two lines in your messaging service:

Android — your FirebaseMessagingService
class Messaging : FirebaseMessagingService() {
    override fun onNewToken(token: String) {
        GraineCalls.onNewToken(this, token)
    }
    override fun onMessageReceived(message: RemoteMessage) {
        if (GraineCalls.handlePush(this, message.data)) return
        // …your own messages
    }
}

React Native and Flutter apps add the same service on the Android side. The calls package and plugin read the token and messages from it, so incoming calls ring even when the app has been closed.

Outcomes

The SDK reports every ring's outcome to Graine. You see it in Call History, in your webhooks (call_declined, call_missed, call_expired) and in the listener:

scheduled→ringing→answered→completed
declinedmissedfailedcancelledexpiredno_device
12 · Scheduling

Scheduled calls New

There are three ways to book a call, and all of them follow the same rules.

  1. The agent books it in conversation when Agent may book calls is on. "Call me tomorrow evening" becomes a call at a time the agent confirms in the user's own timezone.
  2. Your app books it when Users may book calls is on, for example a "Schedule a check-in" button.
  3. Your team books it in the dashboard under Agent → Calls & scheduling → Scheduled calls, for a user by their identifier or for a phone number.

Who the call is for

A scheduled call is booked for a user, never for a device. The user is the one identified by the field you selected under Memory & identity → Who is the user?:

  • Agent-booked: the user in that conversation.
  • App-booked: the user your app passed to identify on that device.
  • Dashboard-booked: the user whose value your team types into the field the form shows, for example Patient ID MRN-000981. Add an optional label such as the patient's name to find the call in the list later.

At ring time, Graine rings the device that user used most recently, among the devices bound to them. A call booked for one patient can never ring a device that only another patient has used. If you change the identifier field later, calls follow the new field from each user's next sign-in. Users who have not signed in can book calls only for the device they are on.

const graine = useGraineClient();

const call = await graine.scheduleCall({ at: new Date("2026-10-14T18:00:00+05:30"), reason: "Daily check-in" });
const upcoming = await graine.scheduledCalls();   // [{ id, at, status, reason, source }]
await graine.cancelScheduledCall(call.id);
let call = try await graine.scheduleCall(at: checkInTime, reason: "Daily check-in")
let upcoming = try await graine.scheduledCalls()
try await graine.cancelScheduledCall(id: call.id)
graine.scheduleCall(at = checkInTime, reason = "Daily check-in") { call, error -> /* GraineScheduledCall, or a GraineError with a code */ }
graine.scheduledCalls { calls, error -> /* upcoming first */ }
graine.cancelScheduledCall(id) { status, error -> /* GraineCallStatus.CANCELLED */ }
final call = await GraineInApp.instance.scheduleCall(at: checkInTime, reason: 'Daily check-in');
final upcoming = await GraineInApp.instance.scheduledCalls();
await GraineInApp.instance.cancelScheduledCall(call.id);
const call = await GraineAgent.scheduleCall({ at: "2026-10-14T18:00:00+05:30", reason: "Daily check-in" });
const upcoming = await GraineAgent.scheduledCalls();
await GraineAgent.cancelScheduledCall(call.id);

The rules every booking follows

  • Times always carry a timezone. The SDK sends the device's timezone, and calling hours and quiet hours are checked in the user's local time.
  • A call rings no more than 10 minutes late. If it cannot ring by then (for example, the agent was switched off), it is marked expired.
  • A call is booked for the user, and rings their most recently used device. A user who signed out everywhere has no device, and the call is marked no_device.
  • Graine checks your credit balance and that the agent is on, both when the call is booked and when it rings.
  • The push that wakes the phone carries only the call name and an opaque call id. Why the agent is calling reaches the agent, never the push.

14 · Design

Design

Design lives in the dashboard's Garage. You set colours, typeface, corners, shadow and motion once, and the assistant bar, the chat window (header, bubbles, suggestions, composer, upcoming calls) and the call screen (scheduled ring, incoming ring, in call, ended, missed) follow them on every platform. 15 · QA

Test it end to end

Run this on a real iPhone and a real Android phone. Push and calls do not work in simulators.

  1. Chat: sign in as test user A and send "hello". Expect a streamed reply and a component when the prompt calls for one. Turn on airplane mode, type a message, then turn it off. Expect the message to send.
  2. Memory: as user A, say "I take metformin at 8 pm". End the chat, start a new one and ask "what do I take in the evening?" Expect the agent to know. Sign in as user B on another phone and ask the same. Expect it not to know.
  3. Consent: call setMemory(false) for user A, repeat step 2 and expect no recall. Then call forgetMemory() and confirm in the dashboard that A has no memories.
  4. Voice: tap the bar, speak, and expect captions and a reply within a second or two.
  5. Outgoing call: tap "Call coach". Expect CallKit (iOS) or the full-screen call (Android), and audio both ways. Lock the screen and the call continues.
  6. Agent-booked call: say "call me in 10 minutes". Expect a confirmed time. Kill the app. In 10 minutes the phone rings; answer it, and expect the agent to know it is a check-in.
  7. App-booked call: scheduleCall 15 minutes ahead, list it, cancel it, and expect no ring.
  8. Decline and miss: decline one ring and let another time out. Expect declined and missed in Call History and your webhooks.
  9. Device limit: sign in as user A on a third device. Expect no memory, and no calls for A on that device.
  10. Sign-out: sign out on a device. Expect it to stop receiving calls for that user.
16 · Launch

Go-live checklist

  • The production publishable key is in the release build, and app:// is in Allowed domains.
  • In-app calling shows Verified for iOS (Production environment) and Android.
  • Memory & identity: the identifier field matches what your app passes. Retention and device limit are agreed with your compliance team.
  • Calls & scheduling: calling hours, quiet hours and daily caps are set. Agent and user booking are on only where intended.
  • Microphone and notification permission texts are final. The Play Console full-screen-intent declaration is filed.
  • Your privacy policy covers voice, chat transcripts, memory, device tokens and scheduled calls (see below).
  • The QA script above passed on both platforms with production credentials.
  • Webhooks are subscribed for the call outcomes you report on.

The trust model, plainly

Because there is no server of yours in the loop, Graine believes what your app tells it about who the user is. Three things keep that safe:

  • Device binding: a user's memory and calls stay with the devices they first used.
  • Limits: per-device and per-workspace rate limits on every request.
  • Nothing personal in pushes, and nothing remembered for anonymous users.

For the strictest setup, set Devices per user to 1 and only call identify after your own authentication. Server-verified identity, where your backend signs the identifier, is planned as an optional upgrade.

Erasure

A user can erase their memories from your app (forgetMemory), and your team can erase any user from the dashboard. Signing out releases the device and stops calls to it.
